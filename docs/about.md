# ocrat

Настольная программа для распознавания текста на изображении. Главное свойство — скорость распознавания. После нажатия «Распознать» текст обычного снимка должен появляться сразу: окно, абзац или кусок интерфейса, сети уже в памяти.

Картинка остаётся на компьютере пользователя: запрос распознавания не обращается к сети и не отправляет изображение на сервер. Языковой модели нет, ни локальной, ни облачной. Текст — символы, прочитанные с картинки.

Языки картинки — русский и английский одновременно. Один проход читает обе письменности, и в поле выводится один текст, в котором русские и английские фрагменты стоят так, как на изображении.

Интерфейс на русском языке. Визуально программа совпадает с [descriptor2000](https://github.com/ukarpenkov/descriptor2000): моноширинный шрифт, прямые углы, рамка в один пиксель, только два цвета.

## Скорость

Скорость считается от нажатия «Распознать» до появления текста. Цель движка: обычный снимок экрана после прогрева сетей укладывается в долю секунды на Apple Silicon и на современном процессоре x64. Это требование к выбору модели, не замер уже собранной программы.

В это время входит декодирование, детекция областей и чтение строк. Загрузка весов в него не входит: обе сети поднимаются при старте worker и остаются в памяти до закрытия программы. Повторное распознавание той же или следующей картинки идёт по уже тёплому движку.

Большой кадр перед детекцией уменьшается по длинной стороне. Число строк по-прежнему добавляет время: каждая строка читается отдельно, поэтому целая страница мелкого текста длиннее одного окна. Две языковые сети подряд не запускаются. Русский и английский читает одна сеть распознавания, иначе второй проход удвоил бы время.

## Платформы

Программа рассчитана на настольный компьютер или ноутбук с одной из двух систем:

| Система | Процессор | Установщик |
| --- | --- | --- |
| macOS | Apple Silicon (arm64) | DMG |
| Windows | x64, он же x86-64 / amd64 | EXE, установщик NSIS |

Windows x64 — это обычный 64-разрядный Windows на процессоре Intel или AMD. В бытовой речи его называют «x86»; в поставке имеется в виду именно x64. Сборщик ставит архитектуру той машины, на которой запущен: macOS — Apple Silicon, Windows — x64. Универсального DMG нет.

Сборки под другие платформы не выпускаются:

- macOS на процессоре Intel;
- 32-разрядный Windows (IA-32);
- Windows на ARM;
- Linux;
- iPhone, iPad, Android и страница в браузере.

## Из чего состоит программа

Оболочка — Electron. Интерфейс — React. Весь код приложения — TypeScript: основной процесс, preload и renderer.

Electron здесь — способ получить окно, установщик и API операционной системы. Три способа подать картинку завязаны на эти API:

- снимок в буфере обмена читается в основном процессе (`clipboard.readImage()`), в том числе скриншот;
- путь к файлу при перетаскивании берётся у Electron (`webUtils.getPathForFile`), а не из объекта `File` в странице;
- выбор файла идёт через системный диалог (`dialog.showOpenDialog`).

React рисует окно. У renderer нет доступа к Node.js: `contextIsolation` включён, `nodeIntegration` выключен, наружу выставлен узкий preload.

TypeScript — язык кода, а не замена оболочки. Отдельная страница или библиотека на TypeScript не читает системный буфер с картинкой, не получает путь при перетаскивании и не собирается в DMG и EXE.

React Native для этой программы не используется. Он рассчитан на iOS и Android. Настольные оболочки React Native for macOS и React Native for Windows не дают того же цикла DMG/NSIS и того же доступа к буферу с изображением, которым уже пользуется descriptor2000.

Граница процессов:

- **main** — окно, буфер обмена, диалог файла, одна операция распознавания за раз;
- **preload** — ограниченный IPC, без произвольного доступа к Node.js;
- **worker** — декодирование картинки и inference вне потока интерфейса;
- **renderer** — React, состояние экрана, темы.

Между процессами достаточно типизированного IPC. Отдельный HTTP-сервер, в том числе внутри процесса, не нужен: операция одна, очередь из одного задания.

## Как это работает

На экране одно изображение. Новая картинка заменяет предыдущую.

1. Изображение попадает в программу одним из трёх способов: вставка из буфера, выбор файла, перетаскивание файла в окно.
2. Кнопка «Распознать» запускает локальное распознавание.
3. В поле появляется текст. Кнопка «Копировать» записывает его в буфер обмена.

Пока распознавание идёт, повторный запуск недоступен. Окно не замирает: inference выполняется в worker.

### Ввод изображения

Принимаются PNG, JPEG, WEBP, BMP, GIF и TIFF. Скриншот macOS и фрагмент из «Ножниц» Windows — это PNG; из буфера изображение может прийти как PNG или как аппаратно-независимый битмап.

Вставка читает буфер в main. Пустой буфер и буфер без изображения (например, только текст) распознавание не запускают: пользователь видит ошибку. Сочетания вставки — Command+V на macOS и Ctrl+V на Windows.

Диалог ограничен теми же расширениями. Перетаскивание принимает файл изображения с диска; перетаскивание текста или ссылки изображением не считается.

### Распознавание

Движок — локальный ONNX Runtime (`onnxruntime-node`). Это конвейер из двух небольших сетей класса PP-OCR mobile с фиксированным графом:

1. детекция текстовых областей (свёрточная сеть, рамки строк);
2. распознавание каждой строки в последовательность символов (свёрточный или SVTR-кодировщик и CTC).

Словарь второй сети общий для обоих языков: кириллица, латиница, цифры и обычная пунктуация. Отдельного переключателя языка нет. Строка на русском, строка на английском и строка, где оба языка стоят рядом, проходят через одну и ту же сеть. В вывод попадают оба языка сразу, одним текстом в порядке чтения. Перевода между русским и английским нет.

Обе сети — обычный OCR на десятки мегабайт, не языковая модель. У них нет текстового промпта, нет авторегрессии по словам и нет генерации. Декодер выбирает символы из этого словаря. Вёрстка, таблицы и Markdown не восстанавливаются, ошибки чтения языковой моделью не правятся.

Системные движки (Vision на macOS и Windows.Media.Ocr) основой не являются: это два разных распознавателя, а на Windows набор языков зависит от установленных языковых пакетов. Один ONNX-конвейер даёт одинаковый код и одинаковый текст на обеих системах.

Веса лежат на диске, в каталоге данных приложения. Сам запрос распознавания сеть не вызывает. Если веса не вложены в установщик, они скачиваются один раз до первого запуска и дальше читаются локально.

Одновременно выполняется одно распознавание. Исполнение inference — CPU. Там, где поставщик выполнения ONNX ускоряет сеть и оставляет данные на машине, его можно включить дополнительно: CoreML на Apple Silicon, DirectML на Windows. Отказ такого поставщика возвращает расчёт на CPU, а не в сеть.

### Результат

Текст — один блок с переводами строк, в порядке чтения. Русские и английские фрагменты остаются вперемешку, как на картинке, и копируются вместе. «Копировать» вызывает в main `clipboard.writeText`. Поле можно выделить и скопировать вручную. Отдельное сохранение в файл в первый выпуск не входит.

## Интерфейс

Две темы. Светлая: белый фон, чёрный текст. Тёмная: чёрный фон, белый текст. Переключатель меняет местами цвет фона и цвет текста. Тема запоминается локально (`localStorage`).

Других цветов нет. Фон, текст, рамка, пунктир зоны приёма файла и заливка кнопки при наведении собираются из одной пары. Кнопки без скругления. Шрифт — моноширинный, как в descriptor2000.

Элементы окна:

- шапка: имя `ocrat` и переключатель темы;
- зона изображения: пустое состояние с подсказкой, предпросмотр после вставки, выбора или перетаскивания;
- кнопка «Распознать»;
- поле текста;
- кнопка «Копировать»;
- короткая строка состояния: ход распознавания или ошибка ввода.

## Что программа не делает

- не отправляет изображение и текст на сервер;
- не содержит локальную или облачную языковую модель и не дописывает текст через LLM;
- не требует учётной записи;
- не переводит текст между русским и английским и не раскладывает результат по языкам;
- не предлагает выбрать один язык распознавания;
- не распознаёт рукопись как отдельный режим и не разбирает таблицы в структуру;
- не ставится на системы из списка вне двух целевых платформ.
