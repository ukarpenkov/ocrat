# ocrat

Настольная утилита для распознавания текста на изображении. После нажатия кнопки распознавания текст обычного снимка экрана должен появляться без заметного ожидания. Картинка остаётся на компьютере: во время работы программа не выполняет сетевых запросов и не отправляет изображение на сервер.

Языковой модели нет. Текст — символы, прочитанные с картинки распознавателем операционной системы.

Русский и английский читаются одним проходом. Строка, где оба языка стоят рядом, остаётся одним текстом в том порядке, в каком фрагменты расположены на изображении. Переводы строк сохраняются.

Интерфейс — строгий минимализм: системные шрифты, прямая геометрия, нейтральные серые границы, без декоративных элементов и без анимаций, которые замедляют работу. Цветовая схема монохромная.

## Платформы

Программа рассчитана на настольный компьютер или ноутбук с одной из двух систем:

| Система | Процессор | Поставка |
| --- | --- | --- |
| macOS | Apple Silicon (arm64) | `.app` и `.dmg` |
| Windows | x64 | `.exe` и установщик NSIS |

macOS — только Apple Silicon (arm64), процессоры серии M. Сборки для Mac на Intel нет.

Windows x64 — обычный 64-разрядный Windows на процессоре Intel или AMD. Сборщик выпускает пакет под ту систему, для которой настроен: macOS ARM64 и Windows x64 готовятся отдельно.

## Функциональность

На экране одно изображение. Новая картинка заменяет предыдущую.

1. Изображение попадает в программу одним из трёх способов: вставка снимка из системного буфера, выбор файла через диалог, перетаскивание файла в окно.
2. Кнопка распознавания запускает локальный OCR.
3. В редактируемом поле появляется текст. Кнопка копирования записывает его в буфер обмена.

Пока идёт распознавание, второй запуск недоступен. Окно не замирает: OCR выполняется вне потока интерфейса.

Пустой буфер, буфер без изображения, файл, который не удаётся прочитать, и сбой распознавателя показывают ошибку и не подменяют уже полученный текст пустым результатом. Повреждённый файл не запускает распознавание.

Программа работает без интернета. Установленная копия запускается без инструментов разработчика.

### Ввод изображения

Вставка читает изображение из системного буфера, в том числе снимок экрана. Выбор файла идёт через системный диалог. Перетаскивание принимает файл изображения; перетаскивание текста или ссылки изображением не считается.

Пути с пробелами и кириллицей допустимы и доходят до распознавателя без порчи.

### Распознавание

Оба адаптера вызываются одинаково: на вход изображение, на выход распознанный текст.

- macOS — адаптер системного OCR этой системы.
- Windows — адаптер системного OCR этой системы.

Готовое приложение несёт свои OCR-компоненты и нужные им языковые файлы. Отдельно установленная OCR-утилита для запуска не требуется.

Одновременно выполняется одно распознавание. Если реализация умеет удерживать уже загруженные данные распознавателя, повторный вызов их не перечитывает.

### Результат

Текст — один блок с переводами строк, в порядке чтения. Поле можно править. «Копировать» записывает текущее содержимое поля в буфер обмена. Длинный текст остаётся в поле и прокручивается вместе с окном. Отдельное сохранение в файл в эту поставку не входит.

## Интерфейс

Две темы. Выбранная тема сохраняется и восстанавливается при следующем запуске.

Светлая:

- белый фон;
- чёрный текст;
- нейтральные серые границы.

Тёмная:

- чёрный фон;
- белый текст;
- нейтральные серые границы.

Других цветов нет. У кнопки различимы состояния: доступна, нажата, недоступна. Окно можно менять в размере; зона загрузки, превью и поле текста подстраиваются под новый размер.

Элементы окна:

- верхняя панель: имя ocrat и переключатель темы;
- основная область: зона загрузки с превью и кнопка распознавания;
- область результата: редактируемый текст и кнопка копирования.

## Архитектура

Оболочка — Neutralinojs. Окно рисует системный webview. Отдельного backend-сервера нет: файловая система, буфер обмена и внешние процессы доступны через API Neutralinojs. Тяжёлого фреймворка интерфейса нет. Ресурсы, которые нужны при запуске, по возможности вкладываются в бинарник как embedded resources Neutralinojs, а не запрашиваются по сети.

Модули:

- UI и состояние интерфейса;
- загрузка и декодирование изображений;
- буфер обмена;
- общий OCR-интерфейс;
- адаптер OCR для macOS;
- адаптер OCR для Windows;
- временные файлы;
- настройки темы.

Общий OCR-интерфейс один. Платформенный модуль подставляет адаптер текущей системы. Остальной код вызывает одну функцию и получает строку текста.

Адаптер — исполняемый файл, упакованный внутрь приложения. JavaScript вызывает его через API процессов Neutralinojs. Пользовательский путь и прочий ввод не склеиваются в shell-команду. Разрешённый исполняемый файл — только вложенный адаптер текущей системы; перед запуском это проверяется. Путь к изображению передаётся отдельным аргументом после проверки, поэтому пробелы и кириллица в пути сохраняются.

Перед распознаванием изображение записывается в каталог временных файлов приложения. После обработки временный файл удаляется. В памяти остаётся превью на экране, без дополнительной копии того же кадра.

Настройки темы хранятся локально и читаются при старте.

Граница простая:

- интерфейс хранит состояние экрана, превью и текст;
- загрузка изображений принимает буфер, диалог и перетаскивание и отдаёт один кадр;
- OCR-интерфейс принимает этот кадр и возвращает текст;
- адаптер текущей ОС выполняет распознавание;
- буфер обмена читает снимок и записывает текст.

## Производительность

Утилита должна оставаться компактной. Зависимостей мало, JavaScript-сборка маленькая, отдельный сервер и тяжёлый UI-фреймворк не добавляются. Распознавание не блокирует отрисовку. Второе распознавание не стартует, пока не закончилось первое. Лишние копии изображения в памяти не держатся.

Ориентиры ниже — планка для замеров, а не измеренные результаты:

- холодный запуск: до 1-4 секунды на современном оборудовании;
- отклик на действия интерфейса: без заметных задержек;
- обычный снимок экрана с текстом: распознавание до 1-10 секунды.

Фактические цифры записываются отдельно, после замера на доступной системе. Пока замера нет, эти числа остаются ориентирами.

## Сборка

Локальный запуск для разработки и production-сборка идут через `neu build` и поддерживаемый builder Neutralinojs.

Пакеты:

- macOS ARM64: `.app` и `.dmg`;
- Windows x64: `.exe` и установщик NSIS.

OCR-бинарник адаптера и языковые файлы входят в установочный пакет. Путь к ним считается от расположения установленного приложения, а не от каталога разработки.

Подписание, notarization и ограничения Gatekeeper и SmartScreen описываются отдельно. Без подписи Gatekeeper и SmartScreen ограничивают запуск скачанного файла. Публичное распространение нельзя считать готовым, пока подписи нет. Готовность сборки конкретной системы отмечается только после реальной проверки этой сборки. Если в текущей среде платформу собрать нельзя, в репозитории остаётся её конфигурация и точные команды, а сама сборка числится непроверенной.

## Границы

- программа не отправляет изображение и текст на сервер и не обращается к сети во время работы;
- в ней нет локальной или облачной языковой модели;
- она не поднимает собственный backend-сервер;
- она не требует учётной записи и не требует заранее установленную OCR-утилиту;
- она не переводит текст между русским и английским и не раскладывает результат по языкам;
- оболочка — Neutralinojs; React, Electron, Rust и Go в эту программу не входят.
